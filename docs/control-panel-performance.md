# 控制台性能与刷新

状态：当前

## 目标

控制台读取的是后端整理后的分页或汇总投影，不在浏览器中扫描运行文件、解析整份日志，或根据原始诊断重新计算业务状态。

## 当前模式

| 场景 | 读取方式 | 前端行为 |
| --- | --- | --- |
| 概览中心 | `GET /api/dashboard` 汇总快照 | 页面保留上次快照，按当前时间范围重绘 |
| 调用日志 | 分页 `GET /api/logs`，详情按需 `GET /api/logs/{id}` | 分页、延迟详情加载、可见时串行刷新运行记录 |
| 图片管理 | 分页 `GET /api/images`，存储统计单独读取 | 列表和统计分开刷新，缩略图按需加载 |
| 实时监控 | `GET /api/monitor/realtime` | 仅在页面可见时串行轮询 |
| 账号、代理、设置 | 各自投影接口 | 缓存快照，操作成功后定向刷新 |
| Studio | 只轮询未终态的图片任务 | 终态任务停止轮询，消息历史保持浏览器本地状态 |

## 统一查询生命周期

`usePageQuery`、`usePagedQuery`、`usePageDebouncedAction` 和页面运行时共同处理加载、刷新、分页、防抖与可见性。后台刷新不应把已有内容替换为空骨架；请求失败也不应丢弃上一次成功快照。

## 约束

- 大字段只在详情接口或明确导出时传输，例如原始诊断、完整请求文本、图片尝试明细和原始 JSON。
- 列表 API 必须有明确分页、筛选和稳定排序，前端不应为得到总数而扫描全部数据。
- 轮询必须串行，避免慢请求重叠后把较旧结果覆盖较新结果。
- 页面切换后停止不再需要的定时器和请求；回到页面时从后端取得新快照。
- 图表只使用后端已计算的时间序列和模型维度，不能在前端根据多类原始日志重新汇总。

性能问题先检查接口投影大小、分页和查询生命周期，再考虑更换组件或重做页面视觉。
