# 控制台操作边界

状态：当前

## 责任分配

控制台操作的校验、持久化和最终结果都由后端完成。前端可以做输入约束、确认弹窗和操作中的禁用态，但不能把本地草稿当成已成功保存的事实。

| 页面 | 主要操作 | 后端事实来源 |
| --- | --- | --- |
| 账号管理 | 创建、编辑、导入、刷新、批量更新、导出、删除 | `api/accounts.py` 与账号服务 |
| 代理管理 | 保存默认出口、代理配置、代理组、连通性测试 | `/api/proxy/*` 与代理服务 |
| 日志管理 | 查看详情、导出、按选择删除 | `/api/logs*` 与日志服务 |
| 图片管理 | 标签、下载、删除、压缩、保留期清理 | `/api/images*` 与 `ImageStorageService` |
| 系统设置 | 保存设置、清理预览 / 执行、备份、存储测试 | `/api/settings*` 与系统服务 |
| Studio | 创建图片任务、恢复轮询 | `/api/image-tasks*` 与图片任务服务 |

## 前端操作规则

- 提交前只保存页面草稿；收到后端成功结果后才更新可见状态。
- 影响多个对象的操作使用后端返回的成功、跳过和失败信息，而不是前端推测每个对象都成功。
- 删除、清理、覆盖和批量状态变更必须有明确的目标集合与确认步骤。
- 失败时保留用户输入和选择，显示后端返回的可展示错误；不要用新的前端文案掩盖诊断。
- 操作完成后重新读取对应的后端投影，或使用该操作的明确返回结果更新本地快照。

## 不可混淆的边界

账号状态、可用额度、账号切换、图片失败分类、清理候选项和存储同步状态都是服务端事实。按钮是否可点击、正在提交、抽屉是否打开和当前表格选中行属于前端本地状态。

新增操作时，应先定义请求模型、返回投影和权限检查，再添加页面按钮。页面不应直接修改 JSON 文件、日志文件、图片索引或账号存储。
