# 前端规则

## 职责和数据流

- `web-vue/src/api/` 是后端契约的传输 Adapter，负责请求、类型和必要的兼容解析，不拥有业务分类。
- 页面与同目录 runtime 负责筛选、草稿、选择、弹窗、轮询、保留快照和响应式布局。
- 页面直接渲染后端的 label、tone、status、diagnostics、capabilities、next actions 和 action events，不根据文本或原始字段二次分类或反算命令。
- 更改业务含义时先完善后端投影；不在 Vue 中先拼接临时规则再复制到其他页面。

## Locality 和复用

- 单页面逻辑、样式和 Module 留在对应 `views/<page>/` 目录。
- 被多个页面真实消费的请求生命周期或交互能力才进入共享 composable。
- 产品专用的 AppShell、业务时间线、操作结果 Drawer、页面表格和 Modal Adapter 留在本仓库。
- 通用控件、键盘行为、浮层定位、主题状态和无业务含义的布局原语可提炼到 Nanocat。
- 不新增只改名或透传全部 props 的 Vue 包装层；现有 Adapter 必须提供布局策略、即时反馈或业务映射等真实 Leverage。

## Nanocat 联调

- 同时修改宿主和 Nanocat 时，开发阶段使用 `D:\nanocat` 本地源码或本地产物联调。
- 不把机器相关绝对路径作为可发布依赖提交。用户验收 Nanocat 后，先在 Nanocat 独立提交；只有明确授权才发布 npm，随后宿主切回正式 npm 版本并重新安装、构建和提交。
- 添加或改变 Nanocat 公共 Interface 前，确认至少两个真实消费者或明确跨项目场景；否则先保留在宿主。
- 宿主不得通过深层导入访问 Nanocat 内部文件，只使用包的公开导出和主题入口。

## 页面生命周期

- 首次无快照时显示稳定加载态；后台刷新保留旧快照，不清空列表或重建页面高度。
- 加载、空结果、错误和保留快照刷新是四种不同状态。
- 弹窗或表单阻止刷新时，关闭后必须存在确定的重新触发点，不能永久保留待刷新状态。
- 轮询只在页面可见且任务未终结时运行；销毁、退出和终态必须清理定时器与请求状态。
- 列表、详情和操作 Drawer 不应因数据后到而闪现、跳高或重复播放动画。固定结构先出现，内容在同一容器内切换。

## 视觉和响应式

- 表格页面保持一页式工作区：工具区稳定，表格在自身容器内滚动，分页和主要操作可持续访问。
- 同一视口区域只能有一个纵向滚动所有者；页面、隐藏 overflow 祖先、表格 body 和 Drawer 不得同时接管同一滚动生命周期。
- 可聚焦的视觉隐藏控件必须锚定在对应可见控件内，不能因内部滚动让焦点目标逃逸并触发祖先容器滚动。
- 桌面和手机端都要检查页面级横向溢出、内部滚动、固定操作、长文本和弹层高度。
- 不把桌面宽度的图表或表格仅靠裁切伪装成移动端适配；需要调整尺寸、轴密度或布局。
- 不嵌套无意义卡片，不用额外背景层、遮罩或阴影修补结构问题。
- 同类 Drawer、Modal、关闭按钮、加载态、表格、标签、下拉菜单和提示层使用同一通用 Module，不在页面复制视觉实现。
- 选中、悬浮、禁用、深色主题和键盘焦点必须是可区分且不相互覆盖的状态。
- 状态文案只描述当前状态，命令文案只描述下一操作；两者不得复用含义模糊的标签。
- 文案和图标对齐、控件高度、圆角和间距应由通用控件 Interface 统一，页面不写一次性偏移修补。

## Vue 变更

- 保持 TypeScript 类型收敛；避免 `any`、重复状态和未消费的返回值。
- 图标使用项目统一入口；生成文件必须通过生成脚本更新和校验，直接依赖需在 `package.json` 声明。
- 新文案使用中文并保持简洁；命令、状态和帮助说明不能互相重复。
- 修改 runtime 时补充 `web-vue/tests/*.mjs` 对真实 Interface 和状态转换的回归测试。
