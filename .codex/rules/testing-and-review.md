# 测试与 Review 规则

## Review

- Review 默认只读，不修改文件、依赖、数据、Git 状态或外部系统。
- 先列问题，按严重程度排序，并给出精确文件和行号；总结和建议放在问题之后。
- 区分三类事实：已提交但未推送、当前未提交、此次新发现。不要把提交历史和工作区差异混成一组。
- 明确区分缺陷、架构深化机会、普通重复和应保留的 Adapter。
- 没发现问题时也要说明测试缺口和剩余风险，不能用“全部完美”代替证据。
- Review 结束后停在编辑门槛；只有用户明确要求修复才进入实现。

## 测试层级

1. 修改所在 Module 的针对性测试。
2. 受影响 Interface 的契约或 runtime 测试。
3. 对应仓库的构建和静态检查。
4. 跨页面、跨存储、并发、安全或发布前改动执行完整回归。
5. 用户可见布局改动执行真实浏览器桌面和手机端检查。

常用命令以仓库当前脚本为准：

```powershell
# Backend
python -m pytest

# Console
Set-Location web-vue
npm run test:runtime
npm run build

# Nanocat, in D:\nanocat
npm run check
npm run build
npm run test:e2e
```

如果当前环境使用 `uv` 或隔离目录，可替换 Python 启动方式，但不得改变测试发现范围。

## 功能和界面验收

- 浏览器 smoke 至少覆盖 Dashboard、Monitor、Studio、Accounts、Logs、Gallery、Proxy 和 Settings。
- 响应式至少覆盖一个桌面视口和一个窄屏手机视口，并检查文档级和内部容器溢出。
- 检查控制台错误、路由加载、暗色主题、弹层层级、键盘焦点和动态内容引起的布局跳动。
- “每个按钮已测试”只能在实际执行对应路径后声明。
- 删除、导入、同步、设置保存、发布等破坏性或外部操作只能在隔离数据、Mock E2E 或用户明确授权的真实环境验证。
- 不因测试通过忽略 Git 完整性；未跟踪生产文件、临时包和本地依赖同样属于发布风险。

## 验证汇报

- 给出实际命令和结果摘要，包括通过数量或构建结论。
- 说明没有运行的测试及原因。
- 浏览器检查必须说明页面、视口和是否执行了写操作。
- 失败测试先判断是实现回退、测试过期还是环境问题，不可直接删掉测试取得绿色结果。
